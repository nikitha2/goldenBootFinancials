# Environment Setup Documentation

## Overview

This project supports multiple environments to facilitate development, testing, and production deployments. Each environment is configured as a product flavor in the Android/Compose Multiplatform build system.

## Configured Environments

- **MOCK**: `http://10.0.2.2:8080/`
- **TEST**: `https://test.bff.goldenboot.com`
- **PROD**: `https://bff.goldenboot.com`

## Build Variants

Build variants are combinations of environment flavors and build types (debug/release):

- `mockDebug`: MOCK environment with debug configuration
- `mockRelease`: MOCK environment with release configuration (minified, optimized)
- `qaDebug`: TEST environment with debug configuration
- `qaRelease`: TEST environment with release configuration (minified, optimized)
- `prodDebug`: PROD environment with debug configuration
- `prodRelease`: PROD environment with release configuration (minified, optimized)

## How Environments Work

### 1. Product Flavors

Environments are implemented as product flavors with the dimension "environment". This is configured in `composeApp/build.gradle.kts`:

```kotlin
flavorDimensions += "environment"
productFlavors {
    create("mock") {
        dimension = "environment"
        buildConfigField("String", "BASE_URL", "\"http://10.0.2.2:8080/\"")
        buildConfigField("String", "ENVIRONMENT", "\"MOCK\"")
        // ... other configurations
    }

    create("qa") {
        dimension = "environment"
        buildConfigField("String", "BASE_URL", "\"https://test.bff.goldenboot.com\"")
        buildConfigField("String", "ENVIRONMENT", "\"TEST\"")
        // ... other configurations
    }

    create("prod") {
        dimension = "environment"
        buildConfigField("String", "BASE_URL", "\"https://bff.goldenboot.com\"")
        buildConfigField("String", "ENVIRONMENT", "\"PROD\"")
        // ... other configurations
    }
}
```

### 2. Build Config Fields

Each environment defines BuildConfig fields that can be accessed in your code:

```kotlin
// Access the base URL
val baseUrl = BuildConfig.BASE_URL

// Check the current environment
val isProduction = BuildConfig.ENVIRONMENT == "PROD"
```

### 3. Environment Switching

All environments share the same source code in `commonMain`. The active environment is selected at build time via product flavors — no separate source sets are needed. Use `BuildConfig.BASE_URL` and `BuildConfig.ENVIRONMENT` to access the current environment's values.

> **Optional:** Gradle supports flavor-specific source sets (e.g., `src/mock/`). If you need code that only runs in a specific environment, create that directory and Gradle will include it automatically. This is not generated by default.

## Best Practices

### 1. Use BuildConfig for Environment-Specific Values

Store environment-specific configuration in BuildConfig:

```kotlin
buildConfigField("String", "API_KEY", "\"your-api-key\"")
buildConfigField("Boolean", "ENABLE_LOGGING", "true")
buildConfigField("Int", "TIMEOUT_SECONDS", "30")
```

### 2. Avoid Hardcoding Environment Values

❌ **Don't do this:**
```kotlin
val baseUrl = "https://api.production.com"
```

✅ **Do this instead:**
```kotlin
val baseUrl = BuildConfig.BASE_URL
```

### 3. Use Resource Values for UI Strings

Define environment-specific app names and strings in resources:

```kotlin
resValue("string", "app_name", "MyApp Mock")
```

### 4. Version Naming

Use version suffixes to distinguish builds:

```kotlin
versionNameSuffix = "-mock"
```

### 5. Application ID Suffixes

Use different application IDs to install multiple environments simultaneously:

```kotlin
applicationIdSuffix = ".mock"
```

This allows you to have MOCK, TEST, and PROD versions installed on the same device.

## Environment-Specific Features

### Debug vs Release

**Debug builds:**
- Include debugging information
- Not minified
- Faster build times
- Larger APK/IPA size
- Enable debugging tools

**Release builds:**
- Minified and optimized
- ProGuard/R8 enabled
- Smaller APK/IPA size
- Better performance
- Ready for production

### Switching Environments

To switch between environments during development:

1. **Android Studio:**
   - Open Build Variants panel (View → Tool Windows → Build Variants)
   - Select desired variant (e.g., `mockDebug`)

2. **Command Line:**
   - Use specific Gradle tasks for the desired environment

3. **IDE Run Configurations:**
   - Create run configurations for each environment
   - Select the appropriate configuration before running

## Troubleshooting

### Build Variant Not Available

If a build variant doesn't appear:
1. Sync Gradle files
2. Invalidate caches (File → Invalidate Caches / Restart)
3. Check for syntax errors in build.gradle.kts

### Environment Values Not Updating

If `BuildConfig.BASE_URL` returns the wrong value:
1. Confirm you selected the correct build variant (e.g., `mockDebug`)
2. Clean and rebuild: `./gradlew clean`
3. Sync Gradle files

### BuildConfig Not Found

1. Make sure `buildFeatures { buildConfig = true }` is set
2. Sync Gradle
3. Clean and rebuild the project
